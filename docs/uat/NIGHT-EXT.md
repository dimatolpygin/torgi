# Боевая ночь расширения — по шагам

Первая настоящая подача из браузера (этап `ext-5`). Ночь **с понедельника 10.08 на вторник
11.08.2026**, подача в 00:00 по Минску, бронь на **18 августа**. Ночь на понедельник
пропускается — эта уже рабочая.

Проверяем на **обоих кабинетах сразу**, бот на эту ночь глушится.

## ⏰ Сначала о времени — это не ваша полночь

Подача идёт по **минскому** времени. Машина, с которой ведётся разработка, живёт в
**UTC+9 (Якутск)**, то есть минская полночь наступает там в **06:00 утра вторника**.

| Шаг | По Минску | На этой машине (UTC+9) |
|---|---|---|
| снять куки | 23:25 пн | **05:25 вт** |
| заглушить бота | 23:30 пн | **05:30 вт** |
| открыть окна | 23:35 пн | **05:35 вт** |
| открыть панель (сверка часов) | 23:50 пн | **05:50 вт** |
| пройти проверку «я не робот» | 23:57 пн | **05:57 вт** |
| выстрел | 00:00 вт | **06:00 вт** |

Дальше в тексте время **минское**. Если работать будете не с этой машины — пересчитайте
под свой часовой пояс, а не под «полночь».

---

## Что здесь делает человек, а что машина

Разделение не техническое, а принципиальное — на нём держится законность всей схемы.

| Человек | Машина |
|---|---|
| Проходит проверку «я не робот» своими руками в каждом окне | Открывает окна, подставляет живую сессию, ждёт |
| Смотрит утром личный кабинет | В 00:00:00.000 отправляет заявку из того же окна той же кукой |

Токен проверки машина ниоткуда не добывает и никуда не кликает. Если человек не подойдёт
к клавиатуре — расширение честно напишет «проверка не пройдена» и не отправит ничего.

## Чего в плане нет

**Входа логином-паролем.** `POST /login/` — ровно та операция, за которую сайт банил IP на
час (ночи 30 и 31.07 потеряны целиком, 0 мест из 4). Вместо входа в браузер переносится
живая сессия бота из Redis. Ноль входов — ноль этого риска.

## Расписание ночи

### 23:25 — снять живые куки кабинетов

```bash
ssh -i .secrets/deploy_key root@45.128.205.148 \
  "cd /opt/bron-bot && docker compose exec -T redis redis-cli --scan --pattern 'bron:sess:*' | while read k; do echo \"\$k \$(docker compose exec -T redis redis-cli get \$k)\"; done"
```

Из вывода собрать `.secrets/night-cookies.json` (файл в git не попадает):

```json
[
  { "label": "жена", "cookie": "<значение gorodid из bron:sess:<логин жены>>" },
  { "label": "муж",  "cookie": "<значение gorodid из bron:sess:<логин мужа>>" }
]
```

### 23:30 — заглушить бота на эту ночь

```bash
ssh -i .secrets/deploy_key root@45.128.205.148 "cd /opt/bron-bot && docker compose stop app"
```

Останавливается **только `app`**: Redis и Postgres остаются, иначе куки было бы не прочитать.

Зачем: бот в 00:00 шлёт 4 заявки без токена — все получат отказ, но 07.08 сайт уже отвечал
`429 Too Many Requests` на частые запросы. Его мусор может подрезать нашу единственную
настоящую заявку, и мы не поймём, дело в защите сайта или в собственном боте.

### 23:35 — открыть окна

```bash
node ext/dev/night.mjs
```

Откроется по окну Chromium на кабинет (свой профиль = своя банка кук), в каждом уже стоит
расширение. Раз в 15 с в консоли строка на каждый кабинет:

```
23:38:15 жена: 21:45 до подачи | 4131195c017pb4 | ПРОВЕРКА НЕ ПРОЙДЕНА | таймер не взведён
```

**Проверить сразу:** виден ли код кабинета. Если вместо него `КАБИНЕТ НЕ ВИДЕН` — сессия
протухла; тогда (и только тогда) войти в этом окне вручную логином и паролем.

### 23:45 — таймер взводится сам

За 15 минут до полуночи в строке появится `таймер взведён`. Ничего нажимать не нужно:
взводит его сама страница, а не панель, — панель всплывающая и умирает при первом щелчке мимо.

### 23:50 — открыть панель в каждом окне (один раз)

Щёлкнуть по значку расширения. Это не косметика: **часы сверяет только панель**, и без
этого выстрел целится по часам компьютера как есть. Панель меряет поправку, отдаёт её
странице, и уже взведённый таймер сам переназначает момент.

Если панель напишет, что часы врут больше секунды — это единственный случай, когда стоит
вмешаться и синхронизировать время Windows. Расхождение в миллисекундах панель не
показывает намеренно и учитывает молча.

Панель можно сразу закрыть — она всплывающая, за полночь отвечает не она, а страница.

### 23:57 — пройти проверку в КАЖДОМ окне

Проверка «я не робот» в форме. По скриншоту клиентки она проходится сама, но если появится
галочка — нажать. После этого **страницу не обновлять**: обновление убьёт токен, а нового
до полуночи может не хватить.

В строке должно смениться на `проверка пройдена (valid)`.

### 00:00:00 — расширение стреляет само

В консоли появятся `POST → /rinki/minsk/create_zajav/` (по одному на место) и итог:

```
=== ИТОГ: жена ===
выстрел: 2 шт., отклонение от цели +48 мс, отправлены одновременно
итог:    Принято 2 из 2 — 2 места на 18 августа, вторник
ответ 0: {"status":200,"text":"{\"code\":\"201\"}"}
```

### 00:05 — посмотреть личный кабинет

Сколько мест реально закрепилось на 18 августа: 2, 1 или 0. Это и есть ответ.

### Утром — вернуть бота

```bash
ssh -i .secrets/deploy_key root@45.128.205.148 "cd /opt/bron-bot && docker compose start app"
```

## Что ночь должна ответить

1. **Принимает ли сервер заявку с настоящим токеном.** Главный вопрос с 04.08: тогда все 4
   заявки бота были отбиты за 11 мс, потому что токена не было вовсе.
2. **Хватает ли одного пропуска «я не робот» на два места** (вопрос A). Если выйдет 1 из 2 —
   ответ найден: нужен свой токен на каждую заявку, это отдельная небольшая доработка.
3. **Какая точность в реальных условиях.** Ожидание 30–80 мс; через прокси будет хуже, чем
   у клиентки напрямую, — на этой ночи это не важно.

## Чего ночь не покажет

Настоящей точности клиентки: трафик идёт через минский прокси, а не с её домашнего
интернета. И ранга в утреннем списке: он решается очередью на сервере сайта и числом
конкурентов, а не нами.

## Если что-то пошло не так

| Что видно | Что это значит |
|---|---|
| `КАБИНЕТ НЕ ВИДЕН` | сессия протухла — войти в этом окне вручную |
| `ПРОВЕРКА НЕ ПРОЙДЕНА` в 00:00 | заявка не отправлена намеренно; токен не был получен |
| `сервер вернул не ответ, а страницу` | защита сработала и на браузерную подачу |
| `сайт отклонил заявку и причину не назвал` | то же, что ловили ночами 06–07.08 |
| `не отправилось (…)` | связь/прокси, а не сайт |
| `429` | ограничение частоты — проверить, точно ли бот был заглушен |
